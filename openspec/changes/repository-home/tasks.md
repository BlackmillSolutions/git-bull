# Tasks

## 1. Git: worktrees and summaries

- [ ] 1.1 Add `Backend::worktrees` in a new module `gitbull_git::worktrees`: `git worktree list --porcelain` through the hardened invocation, parsed into path, HEAD, branch and whether a worktree is bare, detached or prunable, with the main worktree first; implement it in `CliBackend` and in the fake backend (`with_worktrees`) (design, decision 4); verify unit tests of the parser with the output of Git 2.34 and of a newer Git with `locked` and `prunable`, a bare main repository and a detached worktree, and a test in `crates/gitbull-git/tests/` against a real repository with two worktrees
- [ ] 1.2 Add `Backend::summary`: `git status` with the arguments of `flags::STATUS` and `--branch` after neutralising the repository's filters, for the branch or the commit of a detached HEAD, the number of changed files with untracked files, the files in conflict and the paths of the changed files, and `git log -1 --format=%ct HEAD` for the commit time of HEAD; implement it in `CliBackend` and in the fake backend, which records how many summaries run at the same time and can hold them with a gate (design, decision 4); verify tests against real repositories for a branch with modified and untracked files, a clean worktree, a detached HEAD, an unborn branch and a merge stopped with a conflict
- [ ] 1.3 Extend `tests/hardening.rs` with the summary and the list of worktrees: a monitor hook named in the configuration of a repository and of one of its worktrees is not executed, and the index files stay byte for byte unchanged after tracked files were touched (design, decision 4); verify the scenarios "Status read by the home tab" and "Monitor hook in a listed repository" of `git-integration`

## 2. Core: settings and the workspace

- [ ] 2.1 Add `Settings::pinned`, read with `or_default` and filtered like `recent` by `settings::kept`, with `pin`, `unpin` and `forget`, the last of which removes a path from the pinned and the recent repositories; `active_tab: None` stands for the home tab (design, decisions 1 and 6); verify unit tests in `settings.rs` for the scenarios "Settings file without pinned repositories", "Pinned repository outlasts the limit" and "Removed repository" of `app-settings`, and that the pinned repositories survive a save and a load
- [ ] 2.2 Let `Workspace` show the home tab as `active == None`: `show_home` remembers the tab shown before (`shown_before`), `restore` no longer falls back to the first tab, `activate_next` and `activate_previous` pass through the home tab, closing the last tab shows it, and `session_to_save` gives `None` for it (design, decision 1); verify unit tests in `workspace.rs` that a restore with `None` shows the home tab with the tabs restored, that Ctrl+Tab cycles through it, that closing the last tab shows it, and that no session is shown or refreshed while it is shown, for the scenario "No refresh while the home tab is shown" of `application-shell`

## 3. Core: the list of the home tab and its reading

- [ ] 3.1 Add `gitbull_core::repositories::RepositoryList`: the pinned and recent paths, merged into repositories with their worktrees, and their rows with titles, collapsed repositories, a filter by name, path and branch, the selection kept by path and the first match selected while the filter has text, and `left` and `right` (design, decision 2); verify unit tests for the scenarios "Pinned and recent repositories", "Worktrees below their repository", "Worktree opened on its own", "Collapsing the worktrees of a repository", "Folder gone" and "Bare repository" of `repository-manager`, for a filter on name, path and branch regardless of case, a worktree that matches alone, no match, and that reading the rows builds nothing
- [ ] 3.2 Compute when a working copy was last active: the later of the commit time of HEAD and the modification time of the changed files that still exist, at most the first 1,000 of them (design, decision 4); verify a unit test with a temporary folder for the scenario "Last active from a changed file" of `repository-manager`, and one with 5,000 changed files that looks up no more than 1,000
- [ ] 3.3 Add `Overview`: a round of `inspect`, `worktrees` and `summary` jobs in the order of the rows, taken by four worker threads, reported through a channel with `Notify`, cancelled through a `CancelToken`, and applied to `RepositoryList`, which keeps the summaries read before (design, decision 3); verify tests with the fake backend that no more than four summaries run at once, that cancelling drops the jobs not started, that the values of the last round stay during the next, and that a folder gone and a repository Git refuses to read get their states
