# Tasks

> For agentic workers: use OpenSpec Apply only after the user requests
> implementation. Follow this checklist task by task with test-first changes.

**Goal:** provide explicit Git write execution with ordinary hooks and filters,
while preserving protected reads and supporting a single commit without hooks.

**Architecture:** `WriteInvocation` borrows `Git`; both share command building
and process startup, with immutable per-invocation policies. Reuse `Process`,
its pipes and watcher, `Canceller`, `CommandLog`, `TestRepo` and `Marker`.

**Spec:** `specs/git-integration/spec.md` and `design.md` in this change.

**Constraints:** Git 2.34 or newer; the Rust toolchain in `rust-toolchain.toml`;
Linux, Windows and macOS; no new settings, trust dialog, action UI or
`Backend` action method. The existing hardened `write_commit_graph` remains.
Add only a Unix-specific direct dependency on the already resolved
`libc = "0.2.189"` and a Windows-specific one on the already resolved
`windows-sys = "0.61.2"`; update their edges in Cargo.lock and verify notices.
Implementation source and tests stay in `gitbull-git`. New ADRs
describe decisions; the existing read fixtures and scenarios remain valid.

**Implementation branch:** start an `impl/` branch from the reviewed plan
before changing code. CI runs on PRs targeting `dev` or `master` and skips
`plan/` source branches; a plan-only PR cannot establish passing runtime CI.

Each numbered group produces an independently verifiable deliverable. Run
the named tests after its implementation and the workspace suite before
calling the overall change complete. Steps that add new public symbols name
the expected compile failure explicitly. Characterisation guards are marked
as such and are expected to pass initially.

## 5. Windows process ownership

The first Windows CI run of the implementation failed `cancellation_stops_hooks_and_children`: `taskkill /T /F` ended Git and its hook shell but left the hook's background child and that child's subshell alive, holding the stderr pipe, so `wait` returned no result within seven seconds (run 37763491069, job 113265364037). Design decision 5 now replaces it with a Windows job object. The spec delta is unchanged; it already requires that cancellation stops the descendants and closes their pipes. The development machine cannot run Windows code, so Windows CI is the executing verification and a Windows cross target is only a type check.

- [ ] 5.1 Write the Windows-only tests first, in the private `process.rs` tests: `cancellation_terminates_orphaned_descendants` and `cancellation_and_drop_terminate_only_the_job`. Start a tracked process whose Git-bundled shell starts a background child and then exits, leaving the child holding the output pipe. Cancel and Drop must close the pipe within two seconds and no marker may be written afterwards. A sentinel process outside the job must still be running afterwards, and a late cancellation after completion must terminate nothing. The recorded CI failure of the real-Git scenario is the RED for this group; no separate red CI run is required. Type-check the tests with `cargo check --workspace --all-targets --locked --target x86_64-pc-windows-gnu`, installing the target with rustup if needed; if the cross target cannot be installed, say so and rely on CI.
