# Tasks

> For agentic workers: use OpenSpec Apply only after the user requests
> implementation. Follow this checklist task by task with test-first changes.

**Goal:** check out branches, remote branches, tags and commits, and create
branches and tags, from the sidebar, the commit list and the toolbar, in the
manner of GitKraken and Sourcetree, without ever discarding the user's changes.

**Architecture:** typed operations on `Backend` built on `Git::write` (ADR 0007),
refusals read into data in `gitbull-git`, one write action at a time owned by
`Session` (ADR 0008), gestures, menus and dialogs in `gitbull-app`.

**Spec:** the deltas under `specs/` and `design.md` in this change.

**Constraints:** Git 2.34 or newer; the Rust toolchain in `rust-toolchain.toml`;
Linux, Windows and macOS; no new dependency; no stash, discard or force; no
undo, delete, rename, push, fetch or pull. Texts of the interface go into
`crates/gitbull-app/i18n/en-US.ftl`, and every comment, test name and message
in the repository is English. Snapshot tests run on Windows only; the
development machine type-checks the Windows code with
`--target x86_64-pc-windows-gnu`, which is installed, and CI executes it.

**Implementation branch:** start an `impl/` branch from the reviewed plan
(`plan/checkout-and-refs`) before changing code. CI runs on pull requests
targeting `dev` or `master` and skips `plan/` source branches, so a plan-only
pull request cannot establish passing runtime CI.

Each numbered group produces an independently verifiable deliverable and lands
the tests and documentation its own work calls for. Run the named tests after
its implementation and the workspace suite before calling the change complete.
Steps that add new public symbols name the expected compile failure explicitly;
do not treat an unrelated compile failure as the expected RED. Characterisation
guards are marked as such and are expected to pass at once.
