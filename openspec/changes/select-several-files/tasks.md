## 1. Selection model in `gitbull-core`

- [ ] 1.1 Add tests to `crates/gitbull-core/src/file_tree.rs` (or its test module) for the gestures as methods of `FileTree` (design decisions 1 and 3), with no UI: `toggle_file` adds an unselected file and makes it the anchor, removes a selected one and moves the anchor to the nearest selected file above, else below, and does nothing for the only selected file; `select_range` selects the files shown between the anchor and the file, both included, keeps the anchor, skips folder rows and leaves out files in collapsed folders, in the flat list and in the tree; `extend` moves the end from the file last added, one file at a time, shrinks when going back, and stops at the edge of the group; `select_all_shown` selects `files_matching(group, filter)` of the anchor's group, collapsed folders included; `reduce_to_anchor`; a click-like selection of a file in the other group starts a new selection there; a folder selected ends the set; `selected_files` lists the selected files in the order of the list. Verify the module fails to compile because the methods do not exist.
- [ ] 1.2 Implement `also`, `lead` and those methods in `file_tree.rs`; `selected`, `selected_file` and every existing reader keep meaning the anchor. Verify the tests of 1.1 pass and the existing `file_tree` tests pass unchanged.
- [ ] 1.3 Add tests for what keeps and shrinks the set: after `renewed` the set is found again by path, the anchor and `lead` too; a file that left its group drops out; the anchor leaving makes the nearest selected file the anchor before the one-file neighbour rule applies; `set_filter` removes the files the filter hides, keeps the rest, and when none is left selects the first file shown (spec `file-lists`, "Filter hides …"); emptying the filter does not bring files back; collapsing a folder keeps files of other folders and drops those inside it from the range but not from the set when they were selected before. Include a randomised test that renews a tree over many random status changes and compares the set with the expected paths. Verify they fail.
- [ ] 1.4 Implement the renewal with the one-step map of paths, the intersection with the filter, and the handling of the anchor. Verify the tests of 1.3 pass, and that a test with 50,000 files in the group, `select_all_shown` and `renewed`, runs within the budget the existing performance tests of `file_tree` use.
- [ ] 1.5 Add tests for the block successor (design decision 5): `successor_of_selection` returns the first file below the lowest selected row that stays in the group, else the last above the highest, else the first file of the other group, in a flat list, in a tree and under a filter; a selected file in conflict that stays in the group counts as staying (the test names this on purpose); with one file selected it equals `successor_of_selected`. Verify they fail.
- [ ] 1.6 Implement `successor_of_selection` and let `successor_of_selected` call it. Verify the tests of 1.5 and the existing successor tests pass, and `cargo clippy -p gitbull-core --all-targets --locked -- -D warnings` is clean.
