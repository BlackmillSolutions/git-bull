# git-bull 0.4.0

Several files can be selected in the File status view, to be staged, unstaged
or discarded together, and git-bull has a new logo, which is the icon of the
window, of the executable and of every package. Everything else stays as it
was in 0.3.0.

## Selecting several files

- A click selects one file. Ctrl-click, or Cmd-click on macOS, adds a file to
  the selection or takes it out; Shift-click selects the range from the
  anchor to the file; Shift with Up and Down extends or shrinks the range;
  Ctrl or Cmd with A selects every file of the group that the filter shows;
  Escape reduces the selection to the anchor. Space still collapses and
  expands a folder, and there are no checkboxes.
- A selection stays within one group, Unstaged or Staged. A click with a
  modifier in the other group starts a new selection there, and a click on a
  folder leaves the selection as it is. The diff panel shows the anchor, the
  file that was selected first or last added.
- S and U stage and unstage the whole selection while the list has the focus.
  Files in conflict are left out, and when only such files are selected the
  key does nothing. Afterwards exactly one file is selected: the first file
  below the selection that stays in its group, else the last one above it,
  else the first file of the other group.
- The menu of a selected file acts on the whole selection: "Stage 3 files" or
  "Unstage 3 files", "Discard changes of 3 files" with the same question and
  the same journal as one file, and "Copy path", which copies the paths one
  per line. File history and Blame are not offered for several files. The menu
  of a file that is not selected selects it alone first. The button of a row
  acts on its own row and leaves the selection as it is.
- Discarding a selection keeps the rules of discarding a file: what cannot be
  discarded is left out, the dialog says how many files were left, and every
  discarded file can be brought back with "Undo", Ctrl+Z or "Recently
  discarded".
- While several files are selected, the list tells assistive technology how
  many, and each selected row says that it is selected.
- A file that a filter hides leaves the selection and is not selected again
  when the filter is emptied. A range leaves out the files inside a collapsed
  folder. Collapsing a folder keeps the selected files, except when the
  folder holds the anchor: the folder is selected then, and the selection
  ends.

## Logo and icons

The new logo, a bull whose horns end in Git commit nodes, is the icon of the
window on every system, of `git-bull.exe` in Explorer, the Start menu and the
taskbar, of the macOS bundle, and of the AppImage with the sizes of the Linux
icon themes. `packaging/icons/generate.cjs` renders the files from
`packaging/git-bull.svg`.

## Fixes and upkeep

- A test of the list "Recently discarded" failed once on Windows without a
  cause that could be reproduced. The tests now open the list by what is
  drawn and, when one fails, name the buttons that were shown.
- Two crates that crates.io had yanked, `async-executor` and `clipboard-win`,
  are updated.
- Debug builds keep only the line tables, which cuts the size of the test
  programs and so the disk a build of the tests needs.

## Known and open

- Follow-ups of the selection are in issue #50: the focus after a staging that
  failed, the window snapshots of the selection, which were left out because
  the images need a Windows machine, and the third-party notices, which CI
  does not check.
- A refresh that is asked for while git-bull reads the state of a repository
  is not read a second time (issue #36). Follow-ups of the review of the
  discard change are in issue #44.
- Staging a whole folder as one entry, and selecting several files in the
  commit panel, are not part of it.

## Packages

Windows x64, macOS on Apple silicon and on Intel, and Linux x64 as AppImage
and `tar.gz`. How to install them, and what each system needs, is in the
README. The packages carry no developer signature.

## Verification

CI passed on Linux, Windows and macOS for the commit that is tagged. The
selection was tried by hand on a Windows machine before it was merged. Like
0.2.0 and 0.3.0, this release had no pre-release, and its packages were not
started by hand on clean installations of the oldest supported systems.
