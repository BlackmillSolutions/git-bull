# git-bull 0.2.0

The first release that changes a repository: git-bull checks out branches,
tags and commits and creates branches and tags. The home tab becomes a
cockpit for the worktrees of a repository, and the columns of the History can
be arranged. Staging and committing are not part of it yet.

## Checkout, branches and tags

- A double click, Enter or the context menu checks out a branch, a remote
  branch, a tag or a commit. A remote branch is checked out as a local branch
  that follows it. A notice comes before HEAD is detached, and can be hidden.
- A double click on a commit that a branch points to checks the branch out,
  so that HEAD stays on a branch; several branches are offered to choose from.
- Local changes that would be overwritten are never discarded: the checkout
  is refused and a dialog lists the files. There is no force, no discard and
  no automatic stash.
- A branch that another worktree has checked out is marked in the sidebar,
  and checking it out opens that worktree.
- A branch is created from a commit, a branch, a remote branch, a tag or the
  Branch button of the toolbar, and a tag from a commit, lightweight or
  annotated. The name is checked while the user types.
- A tab runs one write action at a time. Closing the tab or the window while
  one runs asks first.

An action the user requests runs with Git's ordinary hooks, filters and
signing ([ADR 0007](../adr/0007-explicit-git-write-invocation.md)); browsing
and background reads keep their protections. How a write action runs is
recorded in [ADR 0008](../adr/0008-write-actions-belong-to-the-session.md).

## Worktree cockpit

- The home tab shows each worktree with a main state, such as at work, new
  commits, ready, paused, done or in conflict, and reads again by itself
  while it is shown.
- Each worktree is compared with its base branch, which git-bull detects and
  the user can set: commits ahead and behind, changed lines, whether the
  branch is merged, and, with Git 2.38 or newer, whether merging it is
  predicted to conflict.
- Commits that arrived since the user last looked are marked, and worktrees
  that change the same files are pointed out.
- A detail panel lists the commits and the uncommitted files of a worktree.
- "Copy as AI context" copies a worktree with or without its diff, and "Open
  remote" opens the page of the repository or of the branch.

## History columns and reference badges

- The columns of the History can be resized, reordered and hidden; the
  arrangement is saved per repository.
- The reference badges of a commit fit the room of the Description column:
  those that do not fit are counted in a badge that names them.

## Known and open

- A refresh that is asked for while git-bull reads the state of a repository
  is not read a second time (issue #36).
- The dialog that offers the branches at a commit has no snapshot image.

## Packages

Windows x64, macOS on Apple silicon and on Intel, and Linux x64 as AppImage
and `tar.gz`. How to install them, and what each system needs, is in the
README. The packages carry no developer signature.

## Verification

CI passed on Linux, Windows and macOS for the commit that is tagged. Unlike
0.1.0, this release had no pre-release, and its packages were not started by
hand on clean installations of the oldest supported systems before it was
published.
