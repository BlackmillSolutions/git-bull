# git-bull 0.3.0

The local Git workflow of the File status view: git-bull stages and
unstages files, hunks and lines, commits what is staged, and discards
changes, with every discard kept so that it can be brought back. Checking
out and creating branches and tags, and the cockpit and the History of
0.2.0, stay as they were.

## Staging

- The File status view lists two groups, Unstaged with the untracked files
  above Staged. A file is staged or unstaged with the button of its row, the
  first entry of its menu, or S and U; Stage all and Unstage all act on the
  files the filter lists.
- A hunk or selected lines of the diff are staged, or unstaged in the diff of
  a staged file, with the entries of the diff, the button on the header of a
  hunk, or S and U. A part is applied as a patch made from Git's own diff;
  when the file changed since the diff was read, nothing is applied and a
  dialog says so.
- Files in conflict, files a filter driver rewrites, symbolic links, changes
  of the file type and diffs that are not loaded in full are staged whole;
  their entries say why.
- Requests made in quick succession are kept and run in order, and the
  selection moves on to the next file.

## Committing

- A commit form below the file list holds the summary, with the count of its
  characters, and the description. With nothing staged, its button is "Stage
  all changes and commit". Ctrl+Enter does what the button does.
- "Amend last commit" replaces the last commit and fills in its message; a
  notice says when that commit is on a remote branch. "Commit without hooks"
  skips every hook for one commit.
- A commit runs the hooks and the signing that are configured. While it runs
  the form offers Stop, which asks Git to end before it ends it.
- During a rebase or a series of patches nothing is committed, because a
  commit there would lose the author of the commit being replayed. A merge is
  concluded with "Commit merge".

## Discarding

- The menu of an unstaged file has "Discard changes", and the title of the
  Unstaged group has a trash button, "Discard all". Both ask first, in a
  dialog that lists the files and says they can be brought back. A hunk or
  selected lines of a tracked file are discarded from the diff without a
  question.
- Nothing is lost for good. Before anything changes, the files are moved, or
  for a part copied, byte for byte into a journal in the Git folder of the
  worktree ([ADR 0009](../adr/0009-discarded-work-is-kept-in-a-journal.md)).
  A bar below the file list names the last discard and offers "Undo";
  Ctrl+Z does the same and Ctrl+Shift+Z discards again. The list "Recently
  discarded" restores older entries, also after a restart.
- A discard that fails puts everything back, and never over a file that
  appeared meanwhile. If git-bull is killed in the middle of one, the entry
  stays and "Put back" completes it.
- A part of a file is refused where Git would rewrite line endings elsewhere
  in the file, and the file can then be discarded whole.
- A discard cannot be stopped, and closing a tab or the window waits for it
  ([ADR 0008](../adr/0008-write-actions-belong-to-the-session.md)).
- A file in conflict, a submodule, a rename and a repository of its own are
  not discarded; their entries say why. What is only staged is unstaged
  first.

## Known and open

- A refresh that is asked for while git-bull reads the state of a repository
  is not read a second time (issue #36).
- Follow-ups of the review of the discard change are in issue #44: the cost
  of listing a journal of very many files, the memory of a part discard, and
  two tests.
- Selecting several files at once is not part of it.

## Packages

Windows x64, macOS on Apple silicon and on Intel, and Linux x64 as AppImage
and `tar.gz`. How to install them, and what each system needs, is in the
README. The packages carry no developer signature.

## Verification

CI passed on Linux, Windows and macOS for the commit that is tagged. The
discard was checked by hand in a real repository, also with git-bull killed
during a discard. Unlike 0.1.0, this release had no pre-release, and its
packages were not started by hand on clean installations of the oldest
supported systems before it was published.
